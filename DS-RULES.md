# Правила дизайн-системы OC-Kontrol

Это правила пользования, а не описание содержимого. Что внутри — в `README.md`, устройство
репозитория — в `CLAUDE.md`.

## 1. Источник один

Значения живут в Figma. Не в коде, не в прототипе, не в старом HTML. Если цвет кнопки в коде
не тот — правится Figma и снимается новый дамп, а не CSS. Правка в `code/` или `components/`
живёт до следующей сборки и создаёт ровно один эффект: расхождение, которое потом ищут
неделю.

Практическое следствие: **несогласие с тем, что показывает система, — это задача в Figma.**

## 2. Токен или честная дыра

У каждого значения либо есть переменная Figma, либо его нет.

Есть — в код едет `var(--accent-default)`. Нет — едет сырое `44px` и запись в `spec.unbound`,
а в CSS появляется маркер `TODO: unbound` с причиной.

Чего система не делает никогда: не подставляет похожий токен. `#30313a` — это одновременно
`--neutral-550` и `--surface-raised-pressed`. Совпадение значения байт в байт не означает
совпадения роли, и выбор роли — работа человека, а не регулярного выражения.

Сейчас непривязанных значений **437 в 72 компонентах**. Это не долг кода — это список мест,
где в библиотеке Figma нет переменной. Четыре повторяющиеся причины:

- нет шкалы размеров контролов (высоты заданы числом);
- нет токена под толщину обводки;
- нет токена под толщину линии иконки;
- пустой контейнер с HUG держит размер из Figma.

Заведёте переменную в Figma — маркер исчезнет сам на следующей сборке. Отредактируете CSS
руками — исчезнет до следующей сборки.

## 3. Имена классов

```
.oc-<slug>                       базовый класс
.oc-<slug>__<part>               часть
.oc-<slug>--<axis>-<value>       модификатор, нижний регистр
```

Ось и значение приводятся к нижнему регистру через дефис: `State=FocusVisible` даёт
`--state-focus-visible`, `Show Icon` даёт `show-icon`.

Имена частей заморожены в `code/_names.json`. Причина не в аккуратности, а в устройстве:
путь части — это положение слоя в дереве Figma (`content/frame-142/frame-5/header-row/signature`),
и выводить имя из него заново означает, что вставленный соседний слой переименует класс у
части, которую никто не трогал. Карта выдаёт имя один раз.

**Имя можно поправить руками** — генератор карту уважает и не перезаписывает. Это
единственный файл в `code/`, который разрешено редактировать.

## 4. Состояния

Каждое значение оси `State` выходит дважды:

- статическим модификатором — `.oc-button--state-hover`;
- псевдоклассом — `:hover`, `:active`, `:focus-visible`, `:disabled`.

Первое нужно витрине, чтобы показать все состояния одновременно. Второе нужно живой странице,
чтобы компонент работал. Наведение и нажатие погашены на выключенном элементе
(`:not(:disabled):not([aria-disabled="true"])`), иначе `disabled` ловил бы `:hover`.

В разметке для приложения ставьте только базовый класс и модификаторы **не**-состояний;
состояние отдайте браузеру. Статические модификаторы состояний — для витрин и скриншотов.

## 5. Размеры и `box-sizing`

Размеры в спеке фигмовские: вместе с рамкой и внутренними отступами. `code/base.css` ставит
`box-sizing: border-box` на всё, что несёт класс `oc-`. Не отменяйте его — при `content-box`
рамка в 1px даёт лишние 2px, а `padding: 12px` — лишние 24px, и компонент перестаёт совпадать
с макетом.

Там же снимаются собственные стили браузера с `button`, `input`, `select`, `textarea` и `a`:
поля, рамка, фон, шрифт. Сброс завёрнут в `:where()`, вес у него нулевой, любое ваше правило
его перебивает.

## 6. Что проверяется и чем

| шлюз | что сторожит |
|---|---|
| `verify.mjs` | листы `components/`, 9 проверок |
| `verify-code.mjs` | `code/`, 5 проверок |
| `tools/check-paths.mjs` | абсолютные пути в скриптах |

`npm run verify` гоняет все три. Любой провал — ненулевой код возврата.

Габарит отрисованного сверяется с размером из Figma **в обоих шлюзах с одинаковыми
допусками**: `0.5px`, если размер записан числом, и `max(1.5px, 1%)`, если размер по
содержимому. Допуски разные по причине, а не по величине: число браузер обязан воспроизвести
точно, а ширину по содержимому он считает сам из ширин глифов, и Figma округляет их иначе.

Разные допуски в двух шлюзах означали бы два разных представления о том, что такое
«совпадает». Меняете один — меняйте оба.

**Покрытие шрифта — проверка 9.** Каждая кодовая точка, которую лист просит нарисовать,
обязана попадать в `unicode-range` вшитого `@font-face`. Непокрытая — провал с указанием
символа и подмножества.

Это не педантизм: символ без глифа рисуется системным шрифтом, выглядит почти правильно и
расходится по ширине. Польские `ł ą ę` так и жили, пока их не поймал CI на Linux. Добавляете
локаль, типографскую кавычку, длинное тире, стрелку — сначала проверка 9 покажет, чего не
хватает, и только потом это чинится вендорингом подмножества.

Обратная сторона: строка «подмножества в ходу» в конце прогона — **единственное основание
снять** подмножество. `cyrillic-ext` снято по нулю, а не по ощущению, что оно лишнее.

## 7. Storybook

`Playground` — крутилки: оси вариантов, текст, переключаемые части. Дефолты берутся из
`props[].default` спеки, а не придумываются.

`AllVariants` прибит к значениям из спеки и крутилок не имеет. Это витрина матрицы и опора
для замера габаритов: протечёт туда пользовательский текст — ширина поедет, и сверка с Figma
начнёт врать.

## 8. Пересборка

```
npm run build
git diff --exit-code
```

Второй прогон подряд обязан дать побайтово те же файлы. Если дифф непуст — генератор
недетерминирован, и это дефект, а не особенность. Поэтому в выходах нет ни одной метки
времени: «когда собрано» пишется в `_build.json`, который в git не едет.

Снимки Figma лежат в `figma-dump/`, поэтому пересборка не требует ни Figma, ни моста. Мост
нужен только чтобы снять новый снимок.
